# Lab2（第四章）实验报告

## 一、实现的功能

开启分页之后，用户传入的地址是用户页表里的虚拟地址，内核不能再直接当指针使用。

- **`sys_get_time`**：借助 `translated_byte_buffer`，把 `TimeVal` 分段写进用户缓冲区所在的物理页。这样即使结构体跨页也能写对。
- **`sys_trace`**：用当前任务的 token 构造临时页表来查询地址。地址不在用户半区、未映射、PTE 无效、缺少 U 位、缺少 R 或 W 位时，都返回 -1。syscall 计数表重新加回到了 TCB 中。
- **`mmap`**：在 `MemorySet` 中检查对齐、`prot` 合法性和是否重叠，然后把 `prot` 左移一位并加上 U，作为区域权限申请 Framed 区域。
- **`munmap`**：先确认范围内每一页都已映射，再按页释放。部分覆盖的区域会被缩短，或者拆分成两个区域。

本地 `make run BASE=2 TEST=4` 下，全部测例通过。

## 二、简答作业

### 1. SV39 页表项的组成与标志位作用

一个 PTE 占 64 位：

| 位 | 字段 | 说明 |
|---|---|---|
| 63–54 | 保留 | 必须为 0 |
| 53–10 | PPN（44 位） | 下一级页表或目标物理页的物理页号 |
| 9–8 | RSW | 留给操作系统自用，硬件忽略 |
| 7 | D（Dirty） | 该页被写过；由硬件置位 |
| 6 | A（Accessed） | 该页被访问过（读、写或取指）；由硬件置位 |
| 5 | G（Global） | 全局映射，在所有地址空间中都存在；切换 ASID 时不必刷新 |
| 4 | U（User） | U 态能否访问。S 态默认不能访问 U 页（除非设置 `sstatus.SUM`） |
| 3 | X | 可执行 |
| 2 | W | 可写 |
| 1 | R | 可读 |
| 0 | V（Valid） | 该项是否有效；为 0 时其余位都没有意义 |

R/W/X 全为 0 时，表示该项指向下一级页表；只要有一位不为 0，就表示叶子项。

举本机上的实际例子：app0 代码页的 PTE 是 `0x208a8c5b`，PPN 为 `0x822a3`，标志为 V R X U A；TrapContext 页的 PTE 是 `0x208ac0c7`，标志为 V R W A D，没有 U 位，所以用户态访问不到。

### 2. 缺页

**(1) 哪些异常可能是缺页导致的？**

- Instruction Page Fault（`scause` = 12）：取指时，页表中找不到对应项、PTE 无效或者缺少 X 位。
- Load Page Fault（`scause` = 13）：读数据时，页表中找不到对应项、PTE 无效或者缺少 R 位。
- Store/AMO Page Fault（`scause` = 15）：写数据时，页表中找不到对应项、PTE 无效或者缺少 W 位。

**(2) 发生缺页时，重要寄存器的值**

- `scause`：上面三个异常号之一。
- `stval`：触发缺页的**虚拟地址**。
- `sepc`：触发缺页的那条指令的地址。处理完成后如果要重新执行它，`sret` 就会回到这里。
- `sstatus.SPP`：发生异常之前所处的特权级。
- `satp`：发生异常时正在使用的页表；我们的内核在 `__alltraps` 中切换成内核页表之前，它就是用户页表。

本机实测：mmap1 申请了只读页后去写它，内核打印 `bad addr = 0x10000000, bad instruction = 0x42e`。这里 `stval = 0x10000000`，`sepc = 0x42e`，`scause` 为 StorePageFault，`0x42e` 处的指令是 `sb zero, 0(a4)`。mmap2 申请了只写页后去读它，`stval` 同样是 `0x10000000`，`sepc = 0x42c`，该处指令是 `lbu a0, 0(a3)`，`scause` 为 LoadPageFault。

**(3) Lazy 策略有哪些好处？**

- 程序启动快：不用一开始就把所有段都从磁盘读进来。
- 节省内存：从未访问过的页（例如没有走到的代码路径、申请了却没有用的内存）永远不会占用物理页，也不会产生 PTE。
- 节省 I/O：没有用到的部分不需要从磁盘读取。

**(4) 10G 连续内存的 SV39 页表大约占多少内存？**

10 GiB / 4 KiB = 2.5M 页，每页需要一个 8 字节的叶子 PTE，合计约 **20 MiB**（即 5120 个页表页）。第二级只需要 5120 个表项，约 10 个页，加上根页表，相比之下可以忽略。所以数量级是 **几十 MiB**。

**(5) 如何实现 Lazy 策略，缺页时如何处理？**

`mmap` 时只在 `MemorySet` 中记下一个 MapArea（范围和权限），不分配物理页，也不写 PTE。
用户第一次访问某一页时会触发 Page Fault，进入 `trap_handler`：

1. 从 `stval` 取出出错地址，在当前任务的 areas 中查找包含它的区域。
2. 找不到，或者访问类型不符合区域权限（例如写一个只读区域）：属于非法访问，杀死进程。
3. 找到并且权限合法：分配一个物理页（清零，或者从文件读入内容），写入 PTE，然后执行 `sfence.vma` 刷新这个地址的 TLB。
4. 返回用户态时 `sepc` 保持不变，于是重新执行刚才那条指令，这一次就能成功。

**(6) swap 策略下，页面失效如何体现在 PTE 上？**

页被换出到磁盘后，把该 PTE 的 **V 位清 0**，此后访问这一页会触发 Page Fault。由于 V = 0 时硬件不会解释其余各位，操作系统可以利用剩下的位（例如原来存 PPN 的位置）记录这一页在 swap 区中的位置。缺页处理时，根据这些信息把页读回，重新填好 PPN 并把 V 置 1。

### 3. 双页表与单页表

**(1) 单页表情况下如何更换页表？**

每个进程一张页表，其中低地址部分是用户空间，高地址部分映射内核，所有进程的内核部分都相同。只有在**切换到另一个进程时**才写 `satp`（并执行 `sfence.vma`，或者借助 ASID 避免全部刷新）。进入和离开内核时不需要更换页表。

**(2) 单页表情况下如何控制用户态无法访问内核页面？**

内核页面的 PTE **不设置 U 位**。在 U 态访问没有 U 位的页，会触发 Page Fault。

**(3) 单页表有何优势？**

- Trap 时不用切换 `satp`，也不用刷新 TLB，系统调用和中断的开销更小。
- 内核可以直接通过用户虚拟地址访问用户数据（只需要临时打开 `sstatus.SUM`），不必像本实验这样先手动查页表、再按页拆分缓冲区。
- 不需要跳板页这种同一个地址映射在两张页表中的特殊设计，trap 入口和出口的代码更简单。

**(4) 双页表下何时需要更换页表？单页表操作系统会选择何时更换？**

- 双页表：每次 **Trap 进入内核**时（在 `__alltraps` 中换成内核页表），以及每次**返回用户态**时（在 `__restore` 中换成用户页表）。这两次切换都在跳板页上进行。
- 单页表：只在**进程切换**时更换，也就是调度器选出另一个进程、执行 `__switch` 切换上下文的时候。如果切换前后是同一个进程的线程，共用同一张页表，就不需要更换。
